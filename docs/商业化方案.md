# 商业化方案（讨论稿）

> 本文仅记录当前产品与计费讨论，不代表已上线的收费承诺。具体价格、权益和重试规则仍需产品确认。

## 1. 产品模式

| 模式 | 当前定位 | 说明 |
| --- | --- | --- |
| 基础模式 | 首期默认能力 | 完成报告记录识别与整理，用户核对后写入档案。识别结果仍需用户确认，不替代医疗判断。 |
| 高级视觉模式 | 未来能力 | 面向更复杂版式、图表或视觉理解场景的增强模式。可以消耗一次识别额度，也可以采用独立计费规则；当前不定价，待能力、成本和体验验证后确定。 |

## 2. 用户权益与购买方式

- **免费体验**：提供有限的基础模式体验额度，帮助用户了解从识别到生成报告记录的完整流程。免费额度、周期和是否可重复领取待产品确定。
- **会员订阅**：按月或其他订阅周期提供额度及可能的会员权益。对用户统一表述为“本月可生成报告数”等报告数量，不展示 token、凭证或模型调用量。订阅价格、额度、有效期、结转与退款规则待产品确定。
- **按次购买**：用户可单独购买报告生成次数，适合低频使用；具体次数、价格、有效期与退款规则待产品确定。
- **BYOK（自带模型 Token）**：允许有条件的用户配置自己的模型凭证，以使用其自行承担费用的模型服务。BYOK 不改变产品对“成功生成报告记录”的识别额度口径，是否免除或调整平台额度需另行定义并经产品确认。

### BYOK 的费用与安全边界

- 用户承担其模型服务商产生的模型费用、账户费用及相关责任；平台不承诺第三方服务的价格、可用性或结果质量。
- 用户密钥应仅用于必要的模型请求，必须按安全方式保存和使用，不导出、不写入报告记录、导出文件、日志或其他健康档案内容，也不向其他用户展示。
- BYOK 的密钥生命周期、存储位置、清除方式及异常处理仍需在服务端和账户方案确定后落地；当前阶段不实现这些收费或账户能力。

## 3. 统一计费单位与扣除规则

- **唯一计费单位：一次成功生成一条报告记录。** 这里的“报告记录”指识别流程成功产出并按产品流程写入档案的一条报告记录，而不是 token、字符数、图片页数、API 请求次数或模型凭证数量。
- 会员额度面向用户显示为“本月可生成报告数”；按次购买显示为可用的“报告生成次数”。界面和帮助文案不暴露 token、凭证或底层模型用量。
- 识别失败、请求失败、校验失败、用户取消，或最终未生成报告记录，均**不扣次数**。
- 同一任务的重试是否重新消耗次数、失败后的额度恢复，以及用户主动重新生成的定义，暂定为**待产品确认**；在确认前不得将重试扣除规则视为已承诺的计费行为。
- 高级视觉模式可沿用一次成功生成扣一次，也可单独采用规则；当前仅保留方案空间，不定价、不承诺具体扣除方式。

## 4. 当前阶段的实现边界

当前只做商业模型文档化，**不新增 `RecognitionUsage`、`recognitionMode` 等数据结构，也不实现额度扣减、会员订阅、按次购买、支付、账户或服务端计费功能**。

原因是目前收费主体、账户体系、支付渠道、服务端部署形态及识别服务边界尚未确定。过早建立使用量或模式字段，可能把尚未确认的收费语义固化到本地数据和导入导出格式中，增加后续迁移成本。

## 5. 未来迁移建议

待收费主体、账户与支付方案、服务端计费时点、基础/高级模式定义及重试规则确认后，再进行最小化设计：

1. 明确“成功生成”的服务端权威事件和幂等键，避免重复扣除。
2. 设计可审计的额度账本（赠送、订阅、按次购买、消耗、退款/恢复），并区分权益来源与有效期。
3. 将模式、套餐和价格配置放在服务端；客户端仅展示用户可理解的报告数量与状态。
4. 迁移现有本地数据时保持向后兼容，不把历史识别记录臆测为已计费用量；必要时通过版本化迁移逐步引入使用量记录。
5. 在上线前补齐失败不扣除、取消、超时、重复请求、重试及 BYOK 密钥安全的测试和审计规则。
